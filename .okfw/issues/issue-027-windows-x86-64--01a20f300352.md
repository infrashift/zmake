# ISSUE-027: Windows x86_64

**Status/Phase:** Open · Phase 27

## Description
zmake did not compile for Windows. The jobserver uses POSIX calls. Other modules compile, but recipes need `/bin/sh`, and the path code knows only `/`. See [ADR-0029](/decisions/adr-0029-zmake-runs-on-windows-x86-64-with-sh-exe-and-a-semaphore-jobserver--01a20f301514.md).

## Acceptance Criteria
- [x] `zig build -Dtarget=x86_64-windows` builds `zmake.exe`, and the unit tests compile for Windows.
- [x] `src/path.zig` holds the DOS file name rules. `dir`, `notdir`, `$(@D)`, `$(@F)`, `abspath`, `realpath`, pattern rules, `VPATH` and the exact-case check use them.
- [x] The parser skips the `:` of a drive name in a rule.
- [x] The default `SHELL` is `sh.exe` on Windows. `$(MAKE)` uses `/`.
- [x] A new pool on Windows is a named semaphore. `--jobserver-style=sem` selects it. A client joins it through `--jobserver-auth=gmake_semaphore_PID`.
- [x] `make cross` builds for Windows. `make dist` adds a `windows-amd64` zip archive. The release workflow checks it on a Windows runner.
- [ ] CI runs the unit tests and a smoke test on Windows.
- [x] The man pages, the docs site and `CHANGELOG.md` tell about Windows.
- [x] `make check` and `zmake check` pass.

## Progress
- 2026-11-24: The code, the docs, the release archive and the CI job are done. `make lint`, `make test`, `make acceptance`, `make cross` and `make docs-style` pass on Linux. The unit tests and the mode tests compile for Windows. The DOS rules have unit tests that run on each system.
- `okfw migrate` moved the wiki to OKF v0.3 and the `x-okfw-*` keys. CI now pins okfw v2026.11.4. `make check` and `zmake check` pass.
- zmake did not run on Windows yet. Wine in a container did not start. The Windows CI job is the first run. Close this issue when that job passes.
