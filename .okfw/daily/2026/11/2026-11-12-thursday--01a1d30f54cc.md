## Notes

- Zig 0.17 removed most `std.posix` wrappers. `main` takes `std.process.Init`. Process spawn is `std.process.spawn(io, ...)`, and `inherit_files` clears `FD_CLOEXEC` in the child.
- okfw writes the H1 from the title. A `--body` that starts with `# Title` gives a duplicate heading.
- `nasa-lint.py` needed two fixes during Phase 1: test helpers are exempt, and `else |_| {}` counts as a swallowed error.
- Zig multiline string literals reject tab bytes. Build tab fixtures with `++` and `\t` escapes.
- nasa-lint found a real R7 issue in `main.zig`: a discarded `failUsage` result. The fix returns `error.Reported` from each failure path.
- Expansion without recursion works with a frame stack and a `pending` call per frame ([ADR-0006](/decisions/adr-0006-expansion-uses-an-explicit-frame-stack--01a1d31ab339.md)). The invariant "the top frame never has a pending call" keeps the loop simple.
- R5 at an average of 2.0 forced a review of each small helper. Most gaps were real postconditions. Some trivial predicates have none, and that is acceptable for an average.
- GNU Make reports the line of the first recipe line in an overriding-recipe warning, not the line of the rule. A side-by-side run with `/usr/bin/make` found this.
- GNU Make deletes a failed target only with `.DELETE_ON_ERROR`. The plan said otherwise. A side-by-side run found it ([ADR-0007](/decisions/adr-0007-delete-partial-targets-by-mode--01a1d327df21.md)).
- A jobserver client needs a private non-blocking descriptor. `/proc/self/fd/R` gives one without a change to the shared pipe ([ADR-0008](/decisions/adr-0008-take-jobserver-tokens-through-a-private-non-blocking-descriptor--01a1d327df28.md)).
- The acceptance suite found a self-aliasing `@memcpy`. The Zig safety checks stopped it, which is a good reason to ship `ReleaseSafe`.
- `zmake check` runs the full gate of the zmake repo.
- The docs work found a bug. A pattern rule drops its order-only prerequisites, because `src/dag.zig` sets `.order_only = &.{}` for a pattern match ([ISSUE-007](/issues/issue-007-pattern-rules-drop-order-only-prerequisites--01a1d3419a7f.md)). Each docs example now runs against the binary first.
- zmake has no built-in variables. An undefined `$(CC)` expands to an empty string, and a leading `-` in the expanded line then acts as the ignore prefix. GNU Make with `-R` does the same.
- A root `ZMakefile` changes discovery. Acceptance scenario 7 ran `zmake -C ROOT` with no `-f`, so it switched to the new file without a failure. It now passes `-f Makefile`.
- Two files with the same dry runs cannot show which file zmake read. Scenario 8 passes `-f ZMakefile`, and strace confirms the discovery.
- The Astro `base` is `/zmake`. Starlight pages use relative links. The landing page builds each link from `import.meta.env.BASE_URL`.
- GNU Make checks the order-only prerequisites of a pattern rule for viability. An unmakeable `| %.d` makes GNU Make skip the rule.
- When the target pattern has a `/`, the stem has no directory part, so `%.dep` gives `main.dep` for `obj/main.o`.
- Lazy functions run in stages on the frame stack. `call` binds $(0) to $(15), so an inner call hides the arguments of an outer call, as in GNU Make.
- GNU Make `call` does not expand a simple variable. `foreach` joins the iterations with a space, also an empty one.
- `zig build test` does not refresh `zig-out/bin/zmake`. Run `zig build` before a manual check of the binary.
