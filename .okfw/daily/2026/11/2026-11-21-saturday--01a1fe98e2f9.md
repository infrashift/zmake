## Notes

- zmake links no libc on Linux. `x86_64-linux-musl` and `aarch64-linux-musl` builds are static. `file` reports "statically linked".
- The Zig linker adds an ad-hoc signature to an `aarch64-macos` binary. The Mach-O file has an `LC_CODE_SIGNATURE` load command with a superblob (magic `0xfade0cc0`). So Apple silicon runs the binary with no `codesign` step.
- The user selected the ad-hoc signature with no notarization, and SHA256SUMS plus a build-provenance attestation.
- The release workflow runs on a tag ref only. A `workflow_dispatch` input for the tag makes the run check out a branch, and then `github.sha` is not the commit of the tag.
- The release workflow calls `ci.yml` with `workflow_call`. Its concurrency group starts with `release-`, so it does not share the `ci-` group of the called workflow.
- `scripts/dist.sh` accepts `0.1.0-rc.1`. It compares the part before the `-` with `build.zig.zon`. A test run in a clone built the three archives, and the verify step passed on the amd64 archive.
